# Bundled entry and design workflows — October 29, 2026

The starting screen offers Open Monaco. Its identity, bounds, revision and
manifest checksum are generated by `data:bundle` and checked against the real
bundled dataset. Choosing that pinned revision prefers same-origin app assets,
even with a different R2 delivery origin configured. Browser caching can be off
without changing an explicit bundled revision into a live road download. Missing
or corrupt selected data fails visibly. Refresh retains its existing behavior.

Static rebundling preserves older immutable revisions for pinned links, writes
decoded chunks for static hosts, atomically replaces the latest pointer, and
rejects changes to immutable files. It no longer deletes the bundled data tree.
Tests exercise old and new revisions and rejected overwrites in temporary roots.
Rebundling the real Monaco input retained the same revision and public files.

Import design accepts supported Citymap version-1 JSON up to 64 KiB, including
Unicode settings and exact large identifiers. It validates map styles, bounds,
view and revision identity and reconstructs settings on the current app origin.
It ignores file-supplied URLs. Old optional settings retain their defaults;
synthetic maps require test builds. A late read cannot replace a newly chosen
map. Imported settings do not include road geometry or create an extra save.

Saved designs show their save date. Renaming changes their saved title without
changing the map label, settings, identity or timestamp. Update saved design
replaces its settings in place, preserves the custom saved name and ID, and sets
the save date. Save design remains available to create another copy. Storage
failures leave existing records visible and their settings can still be exported.
Import and saved-list UI live in separate Svelte components; parsing loads only
when importing. No runtime dependency was added.

Validation passed **285 unit tests, 118 local Chromium browser cases and 11
built-app Chromium cases**, plus type checks, lint, code generation, the normal
production build and offline deployment validation. The local shortcut also
passes its 214 selected unit cases. Browser coverage includes real downloads,
file input, malformed/oversized files, cancelled reads, rename/update/reload,
failed deletion, long names at desktop/phone widths and zero provider calls for
Monaco and its pinned link. Existing rendering, source-integrity and road-loader
regressions pass. Desktop and narrow-screen screenshots were inspected.

The production entry is 45.93 kB gzip, below the existing 100 kB preflight limit.
No live-provider latency or deployed R2 delivery measurement is claimed. Shared
R2 cell filling is a separate server milestone; this work improves the existing
prepared dataset and browser paths.
