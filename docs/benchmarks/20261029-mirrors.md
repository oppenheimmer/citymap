# Optional Overpass failover, 2026-10-29

`VITE_OVERPASS_FALLBACK_URL` prepares one independent backup for viewport loads.
It is empty by default. The existing retry can change endpoints after connection
failure or HTTP 500/501, with the existing backoff and request budget. Cached
recovery runs first. No parallel hedge, extra retry or endpoint loop is added.
The selected backup remains active for that map session, including manual retry.

the same public service, invalid/relative URLs and URLs containing a username or password.

## Retry and cache invariants

- No switching for 429, provider busy (502–504), readable Retry-After, query or
  resource failures, invalid data, background-processing failures or cancellation.
- Every actual provider request keeps its appropriate public-provider queue.
  A backup-enabled map uses one request at a time even for private endpoints.
- The provider changes only when a backup request is actually dispatched. Older
  cache recovery cannot report a backup switch that never happened.
- Fresh cache data from either configured provider can satisfy a revisit.
  Outage recovery prefers fresh records over older ones, then the newer eligible
  older record. Stored coordinates keep their actual provider's key.
- Split children can come from different providers, but a mixed parent is not
  stored under a single provider's identity. Reports keep source origins and
  request counts; URL paths, queries and credentials are omitted.

## Local evidence

Ten new unit tests in `tests/live-providers.test.ts` check the rules above using
controlled time. Local browser cases exercise the real cells worker and
IndexedDB with separate primary/backup fixture routes. They verify the delayed
same-query retry, source-specific cache reuse, a failed backup stopping at two
total attempts, explicit retry staying on the backup, an unreachable primary,
and preserving a primary 429 wait. Existing rendering/export/storage suites guard
the surrounding behavior. Unit coverage of `providers.ts` is 100% of lines and
branches; this does not imply whole-application coverage or live service uptime.

Final mirror validation passed 266 unit tests, all 102 local browser cases and all
11 built-app cases. The additional built-app case compiles a reserved mock backup
URL through `VITE_OVERPASS_FALLBACK_URL` and verifies the actual runtime switch and
report. The surrounding suites also cover rendering/export parity, older-cache
recovery, cache clearing, split reuse, real Monaco data and whole-area rollback.
Svelte/TypeScript checks, lint, generated-data verification, the restored normal
production build and offline deployment validation passed. No runtime dependency
was added, and neither public candidate was enabled by default.

Remaining experiments are query-geometry cropping and adaptive batch sizing.
Cropping requires explicit gap handling, seam/hash equivalence and payload
measurements before changing the query schema. Existing cached coordinates are
kept compatible; no speculative query-format migration was activated.
