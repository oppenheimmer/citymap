# Real offline-extract pilot — October 9, 2026

The pilot uses the dated [Geofabrik Monaco extract](https://download.geofabrik.de/europe/monaco.html)
`monaco-261006.osm.pbf`: 691,615 bytes, snapshot
`2026-10-06T20:21:06Z`, SHA-256
`81dca271b5cc4e33c4c9da2f906c218ba938374a8ba953414f5ce07d983435dc`.
Its published MD5 was checked after completing the download. The actual
[Monaco boundary relation](https://www.openstreetmap.org/relation/1124039),
version 74, was assembled from the full OSM relation download. Monaco is a
city-state; this does not establish coverage of larger or unrelated cities.

The optional Pyosmium 4.3.1 reader preserves decimal IDs as strings and streams
local primitives. The TypeScript extractor indexes nodes on disk using Node 24
SQLite, then selects complete highway ways touching the E7 polygon. It includes
crossing segments with both vertices outside, keeps all referenced endpoints,
preserves highway/bridge/tunnel/layer tags, and rejects incomplete references or
ambiguous geometry. No clipping or road simplification is applied.

Extraction selected **3,486 ways, 13,842 unique referenced nodes and 15,369
segments**. Default full-detail output is one object; a 2,048-point budget
produces ten independently validated chunks. The retained compressed input is
237,083 bytes, used only by local tests. The normal frontend still ships just
its small synthetic sample.

## Format measurements

[Raw measurements](20261009-monaco.json): Node 24.20.0, Linux x64, Intel
i5-1345U, one warmup and ten measured iterations, fresh child process per format.
All formats have the same 15,369 segments. The two V2 layouts preserve every
quantized E7 coordinate exactly. V1 retains its documented float32 rounding.

| Format | Chunks | Stored gzip bytes | Median decode/walk total | Sampled heap increase | Process peak RSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| V1 | 1 | 158,405 | 26.978 ms | 6.43 MiB | 101.70 MiB |
| V2 single | 1 | 106,614 | 23.033 ms | 11.96 MiB | 104.34 MiB |
| V2 chunked | 10 | 111,518 | 27.593 ms | 11.85 MiB | 111.31 MiB |

V2 reduces wire size here. Its retained decoded representation uses more heap
than V1 in this particular measurement, and the small chunk budget adds CPU and
request overhead. These numbers do not prove lower browser peak/worker/GPU
memory or faster complete-city drawing. Heap growth is sampled and process RSS
includes runtime/module overhead. Network, projection, upload, exports and
physical-device performance are excluded from this format measurement.

Local Firefox browser checks consume the actual gzip HTTP objects, validate all
chunks, export all segments to SVG and reopen an immutable revision link. A
corruption case rejects decoded bytes without live fallback, then verifies that
explicit retry reloads the corrected bytes rather than the poisoned HTTP cache.

Sources and reproducible commands are recorded in the
[real-city fixture guide](../../tests/fixtures/real-city/README.md).
No dataset or infrastructure was uploaded or deployed.
